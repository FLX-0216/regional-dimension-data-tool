## OPS 数据统一合并：第十四轮（修复上传同名文件 PermissionError）

- 问题：上传 `FY25Q2Union.xlsx` 报 `PermissionError: [Errno 13] Permission denied`。
- 根因：`load_from_uploads` 把上传文件直接以原始文件名写入 `_streamlit_uploads/`；若此前已上传过同名文件且该文件仍被占用/锁死，再次覆盖写入会失败。
- 修复：
  - `app.py` 新增 `import uuid`；
  - `load_from_uploads` 给临时文件名加唯一前缀：`f"{uuid.uuid4().hex}_{up.name}"`，确保每次上传都是新文件，避免同名覆盖冲突。
- 编译通过；Streamlit 干净重启（HTTP 200）；skill 已同步 app.py。

## 第二十二轮（save_bucket PermissionError：历史Union 写 Parquet 被锁）
- 现象：跑 4 个 Q 的 Union 保存时 `save_bucket` 写 `data_历史Union.parquet` 报 `PermissionError: [Errno 13] Permission denied`。
- 根因：环境里残留 2 个旧 Streamlit 幽灵 python 进程（PID 9916 / 47488），一直占用桶 Parquet 文件句柄，导致当前进程写入被拒。
- 修复（`app.py`）：
  - 新增 `_atomic_write_parquet`：先写唯一临时 `.tmp.parquet`，再 `os.replace` 覆盖目标；遇 `PermissionError` 重试 20 次（每次 sleep 0.3s），原函数 `finally` 中 `os.remove` 临时文件（沙箱拦截则忽略）。
  - `save_bucket`、`save_mapping` 均改走 `_atomic_write_parquet`（`clear_bucket_with_progress` 内部也用 `save_bucket`，自动覆盖）。
  - `main()` 开头加 `_cleanup_stale_tmp()`，启动时清理上次因锁残留的 `.tmp.parquet`（best-effort）。
- 运维：用 `Get-Process python* | Stop-Process -Force` 杀光全部 python（含 2 幽灵 + 旧 server 27672），再单实例重启；重启后仅剩 2 个 python（streamlit launcher 55032 + app server 60704 占 8501），无幽灵。HTTP 200，启动日志无报错。
- 经验：Streamlit 正常运行是「launcher + app server」两个 python 进程、仅 app server 占 8501；若出现 ≥3 个且只有 1 个占 8501，多半是旧重启残留幽灵进程，会锁住桶 Parquet，需全杀重启。
