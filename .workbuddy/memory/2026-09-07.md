## 启动.bat 编码 bug 修复
- 现象：双击 启动.bat 后 cmd 里所有中文 echo 行乱码，且 echo/`start`/`http:`/`echo.` 被当命令报"不是内部或外部命令"。
- 根因：`.bat` 含 UTF-8 多字节字符（中文 echo + 引用中文文件名 `使用说明.txt`），`cmd.exe` 解析器对多字节分词有 bug，把字节拆成独立命令；`chcp 65001` 不能解决。
- 修法：`.bat` 重写为 100% 纯 ASCII（英文 echo + 英文标题 + 不引用中文文件名），中文说明放独立的 `使用说明.txt`。验证命令：`grep -P "[^\x00-\x7F]" 启动.bat` 应无输出。
- 已同步：源项目 + OneDrive 共享目录 `Sales Data Analysis\启动.bat` 均覆盖为纯 ASCII 版；commit `bfbfc88` 已推 GitHub。

## FCST 分析：上传 Week10 后显示 0 + Cycle 排序错乱
- **Bug A（数据 = 0）**：上传 Week10 后，FCST 分析选 Week10 当前 FCST = 0，但对比 Week8 有 467,655。
  根因：`_load_fcst_analysis_data` 用了 `@st.cache_data`，缓存 key 只含 `(fy, mapping mtime)`，不含数据桶 mtime → 上传新数据后缓存仍返回旧 fcst（无 Week10），过滤得到 0 行。
  修法：把 `FCST / DG&Quota / 历史Union` 三个数据桶的 `os.path.getmtime` 加进缓存 key；任何上传/清理改写 parquet → mtime 变 → 缓存自动失效。
  新增模块级 helper：`_bucket_mtime(type)` 和 `week_sort_key(w)`。
- **Bug B（排序）**：`cyc_opts = sorted(...)` 是字母序，导致 Week10 排在 Week2 前面。改为 `key=week_sort_key`（提取数字再排序），自然升序 Week1,2,…,13。
